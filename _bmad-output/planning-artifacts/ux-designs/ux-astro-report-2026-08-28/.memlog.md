- (decision) Scope: whole operator app end-to-end (chart input -> report generation -> output). Goal is a base UX spec to rebuild the current clunky interface into a new complete one, with proper loaders, toasts and feedback states.
- (decision) Primary palette #42297a on white background. Tailwind acceptable as the implementation vehicle.
- (decision) Visual reference for padding/spacing/color-contrast rhythm: https://matricedeldestino.it/matrice/16-02-1986
- (decision) Sources: ARCHITECTURE-SPINE.md only. No prior design artifacts exist.
- (assumption) Working mode: fast path — batch gap questions, draft both spines with [ASSUMPTION] tags, use creative tools (color theme + key-screen mocks) at Finalize since this is a visual rebuild.
- (event) Extracted ARCHITECTURE-SPINE.md: single principal (Argon2 password + session cookie, no users table); 8-stage checkpointed ReportRun (natal_ready->transits_ready->payload_ready->draft_ready->gate_passed->exported); HTMX 2.x pinned; WeasyPrint PDF export; Jinja2. UI surfaces implied: Client record + natal chart, chart wheel (operator verification only), Domain Profiles, monthly transit run, Report Payload view, Draft view, Report review, Gate result, Corpus collection, Style Guide editing, logical backup/export with staleness warning.
- (event) Audited current UI: shell/http/templates/ has 16 standalone full-HTML Jinja templates with NO base template, NO template inheritance, NO CSS file, NO static assets. Semantic HTML with role=alert, labels, autocomplete present (accessible bones) but zero visual design. HTMX loaded ad hoc from unpkg CDN inside report_run_poll.html only, polling every 2s with hx-swap outerHTML. Routes: /login, /clients(+new/edit/delete/{id}/reports), /clients/{id}/chart, /clients/{id}/report-runs, /report-runs/{id}(+/payload /draft /report /export/pdf /export/markdown /export/disposition), /style-guide(+/edit /{version}), /corpus(+/new), /backup, /healthz.
- (decision) Reference site matricedeldestino.it design DNA (measured): Inter font; body 16px/1.5 ink #111827 on #fff; muted text 14px/20px; primary = Tailwind violet scale (100 #EDE9FE, 300 #C4B5FD, 400 #A78BFA, 500 #8B5CF6, 600 #7C3AED, 700 #6D28D9, 900 #4C1D95); headings primary-700, buttons primary-600; type steps 20/24/30/36/48 weight 700; 4px spacing base; heading margins 16-24px; container pads 16/24/32/48; content widths prose ~672-896px, page shell 1280px; radius 6-8px buttons/cards, 12-24px large cards, 9999px pills; subtle shadows; dark mode supported; feel airy/centered/editorial.
- (decision) Palette: #42297a is the anchor. Build a full 50-900 ramp from it; primary-700 = #42297a drives primary buttons and headings; accent/link ~#5b3fa0. Cooler/deeper than the violet reference.
- (decision) Navigation shell: persistent left sidebar (~240px) with app name, the 6 areas, active-state highlight, sign-out pinned at bottom; content area to the right with its own max-width. Sidebar collapses to a drawer below tablet width.
- (decision) Density: mixed. Compact rows (~40px, 8-12px cell pad, hairline dividers) for client lists and report history; airy spacing (20-24px field rhythm, 32-48px section gaps, 640-720px prose width) for the chart-input form and the 8-section report review.
- (decision) Dark mode: in scope for v1. Author both light and dark palettes in DESIGN.md as CSS-variable tokens; wire to prefers-color-scheme plus a manual toggle in the sidebar.
- (assumption) Typeface: Inter for UI (matches reference, free, strong at dense sizes); system monospace for IDs/hashes/ephemeris identity. To confirm at Finalize.
- (assumption) Report review view is a document-like reading panel (~720px, generous line-height) visually distinct from app chrome, with in-page section navigation for the 8 sections. To confirm at Finalize.
- (assumption) Feedback primitives: skeleton loaders for page/section loads; inline spinner + disabled control for actions; the report-run poll becomes a named-stage progress indicator (natal->transits->payload->draft->gate->export); toasts top-right, ARIA live, success auto-dismiss ~5s, errors persist until dismissed.
- (assumption) Scope boundaries: desktop-primary (single operator on a laptop), responsive down to ~768px as courtesy; no PWA/offline; operator UI in English, report content in Italian, no i18n framework; accessibility floor WCAG 2.1 AA, full keyboard, visible focus, honors prefers-reduced-motion.
- (event) Flow audit: no '/' index route (operator lands nowhere). start_report_run drives the whole pipeline synchronously inside the POST; poll_report_run re-drives it on every 2s GET. Gate failures render as raw text + <ul> on report_draft.html. Payload view is an untyped recursive <dl>/<ul> dump. Corpus list inlines a full <pre> of every past report. Style guide view is a <pre>. Destructive/supersede confirms are bare pages. Backup-stale warning appears only on client_reports.html. Forms redirect on success with no confirmation feedback; errors are role=alert <p> at top of page.
- (decision) IA: sidebar top-level = Home (new dashboard surface), Clients, Style Guide, Corpus, Backup. Chart wheel and Report runs are nested under a Client via a contextual tab row (Record / Chart / Reports), not top-level. Home shows recent runs, global backup-staleness, and quick actions.
