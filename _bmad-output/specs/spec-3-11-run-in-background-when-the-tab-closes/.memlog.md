- (direction) Source: sprint-change-proposal-2026-09-14.md (correct-course, approved), consuming AD-20 amendment in ARCHITECTURE-SPINE.md — routed here per its Implementation Handoff step 2.
- (decision) Why is a mandate-to-meet + pain-to-solve: Francesco requested (not a defect) a way to stop being tied to keeping the tab open while a report generates; today's poll-only design (AD-20 pre-amendment) pauses forward progress the moment the tab closes.
- (capability) CAP-1 Select run mode deployment-wide: REPORT_RUN_MODE (poll|background, default poll) read once into Settings via shell/config.py, never set per-run.
- (capability) CAP-2 Background advancement: in background mode, an in-process scheduler task (started at app startup, stopped at shutdown) ticks advance() for every ReportRun with failed_at IS NULL and stage != gate_passed, so runs keep advancing with the tab closed.
- (capability) CAP-3 Read-only poll in background mode: the poll handler (GET /report-runs/{run_id}) renders current state without calling advance() when REPORT_RUN_MODE=background, so scheduler and poll never race to double-advance the same run.
- (constraint) The scheduler must call the same advance() under the same Postgres advisory lock as poll mode (AD-20/Story 3.10) — no second advance path, no change to AD-10 stage semantics, idempotence, or failure/regeneration counters.
- (constraint) poll mode must remain byte-for-byte Story 3.10 behavior — REPORT_RUN_MODE default is poll, and its regression tests must pass unchanged.
- (constraint) No queue, broker, or second deployable — background mode stays single-process/single-service (Render plan Francesco already provisioned), per AD-20 amendment and the Deferred section's worker/queue reservation for a scale change that hasn't happened.
- (constraint) background mode requires a Render plan with no idle spin-down; this is a documented deployment prerequisite (AGENTS.md follow-up), not something the app enforces or detects in code.
- (constraint) A run rewound to payload_ready pending human Gate review (Stories 5.7/5.8) is ticked by the scheduler like any other incomplete run — no special-case pause, still bounded by AD-10's existing stage_failure_count/_MAX_STAGE_FAILURES.
- (assumption) No boot-time reconciliation pass after a dyno restart/redeploy — resuming is left to the next poll or the next post-restart scheduler tick; Francesco explicitly accepted this gap, so it is a constraint (accepted risk) rather than an open question.
- (non_goal) No worker-process/queue-broker architecture — out of scope, reserved in ARCHITECTURE-SPINE.md's Deferred section for if the 200-reports-per-month ceiling moves.
- (non_goal) No boot-time reconciliation pass on restart — accepted gap, not built.
- (non_goal) No app-level enforcement or detection of the Render no-spin-down prerequisite — documented only.
- (non_goal) No change to the JS poll-retry backoff (shell/shell.js POLL_BACKOFF_MS_*) — scoped out of this proposal as an independent, already-shipped change (see spec-reduce-poll-retry-backoff-to-1-2s.md).
- (non_goal) No schema or migration change — ReportRun is untouched.
- (decision) Success signal: REPORT_RUN_MODE=poll reproduces Story 3.10 exactly (unchanged regression tests green); REPORT_RUN_MODE=background advances a run to gate_passed (or a terminal failure) with the browser tab closed throughout, and the stage-track view (Story 9.5), when reopened, renders identically to continuous-polling behavior.
