## Intent

**Problem:** Story 9.5's Gate-failure panel (`/report-runs/{id}/draft`) already
shows an Italian `kind_label` per violation, but `violation.detail` (e.g.
"claims date 8, but none of the cited entries assert a date fact.") is raw
English generated by `core/gate/run.py` — Story 9.9 explicitly fenced `core/`
off as "out of reach" when it swept the rest of the UI to Italian, leaving
this the one remaining English surface Francesco sees. Cited `entry_ids` also
render as bare opaque hash chips, forcing Francesco to cross-reference the
Payload view by hand to see what data actually triggered the failure. The
run-stage view's "Vedi bozza" link on a Gate failure is also a plain
unstyled `<a>`, giving no visual signal that the run is in an error state.

**Approach:** Translate every `GateViolation.detail` string to Italian at
the source (`core/gate/run.py`'s four detail-generating call sites) since it
is pure copy, not behavior, and the app's own stated goal is zero English in
rendered UI. Resolve each violation's `entry_ids` against the run's already
-loaded `ReportPayload` and render each cited entry as a small labeled card
(Italian field labels, localized timestamps) inside the violation card,
alongside — not instead of — the existing copyable id chip. Restyle the
poll view's Gate-failure "Vedi bozza" link as a centered, danger-styled
button reading "Verifica non superata".

## Boundaries & Constraints

**Always:**
- `detail` strings become Italian prose, same facts, wording only.
- Cited-entry preview is additive inside `.violation-card` in
  `report_draft.html` only; `report_payload.html`'s raw-key `<dl>` dump is
  untouched (separate, pre-existing gap).
- Entry lookup/labels live in `shell/http/stage_view.py` (pure, no I/O),
  mirroring `VIOLATION_KIND_LABELS`; id→entry index built once per request
  from the already-loaded `stored_payload.payload`, never a new query.
- Cited-entry timestamps localize via `client.iana_zone` through the
  existing `_localize_value` walker (`shell/http/payload_view.py`),
  `dd/MM/yyyy HH:mm` — never raw UTC ISO.
- The "Vedi bozza"→"Verifica non superata" restyle touches only
  `report_run_poll.html`'s `{% if gate_failed %}` branch; other branches
  unchanged.
- New CSS uses existing semantic tokens only (`.btn--danger`, `.badge-mono`,
  `--border-hairline`, `--surface-sunken`, `--radius-md`, `--space-*`) — no
  new colors.
- Planet/sign identifiers inside `asserted`/`gathered`/`unmatched`/`gathered`
  sets (`_invented_detail`/`_contradicted_detail`) and inside a cited-entry
  card's `transiting_body`/`natal_point`/`body` fields are Payload-internal
  English canonical keys (`_BODY_MAP`/`_SIGN_MAP` *values*, e.g. `"saturn"`,
  `"leo"`) — not Italian vocabulary words. Translate them too, via one small
  reverse-lookup Italian display map, applied at both sites (review-loop 1:
  the original Never clause below was wrong).
- That reverse-lookup map covers all fourteen values a `natal_point`/
  `transiting_body`/`body` field can actually carry, not just the ten
  classical planets: `core/transits/aspects.py::_natal_targets()` also
  admits `"true_node"`, `"south_node"` (both already on `chart.planets`),
  `"ascendant"`, and `"midheaven"` — plus the twelve signs (review-loop 2:
  review-loop 1's map, and this bullet's own prior "10 planets + 12 signs"
  wording, missed these four; `_body_sign_facts()` reads `natal_point` into
  `gathered`, so an untranslated angle/node leaks into the `detail`
  sentence itself, not only the cited-entry card).
- `resolve_cited_entries`'s id→entry index is built once per HTTP request
  (`view_report_draft`), not once per violation — a multi-violation draft
  must not re-walk the same `stored_payload.payload` from scratch for each
  one (review-loop 2: the prior "once per call" fix under-delivered this
  Always bullet's own original wording).

**Ask First:** none — copy/presentation change plus one pure helper; no
route, status-code, or data-model changes.

**Never:**
- No change to `GateViolation`'s fields, `run_gate()`'s pass/fail logic, or
  `StoredGateResult`'s shape.
- No change to `report_payload.html`, Accetta/Modifica-e-ricontrolla, or
  Rigenera.
- Don't change `_BODY_MAP`/`_SIGN_MAP`'s existing Italian→English direction
  or invent new canonical keys — add a separate, display-only English→
  Italian reverse map instead. Day-list keys (`giorni_favorevoli`, …) are
  genuinely already Italian and stay untouched.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Contradicted body/sign | `asserted={"saturn"}`, `gathered={"moon"}` | `detail == "afferma Saturno, ma le voci citate confermano Luna."` | N/A |
| Invented date | `asserted={8}`, category `"date"` | `detail == "afferma il giorno 8, ma nessuna delle voci citate lo conferma."` | N/A |
| Contradicted house | `unmatched={7}`, `gathered={5}` | `detail == "afferma la casa 7, ma le voci citate confermano la casa 5."` | N/A |
| Retrograde contradiction | category `"retrograde"`, `gathered={False}` (the only reachable contradicting value — `asserted` is always `{True}`, so `gathered={True}` never produces a violation) | `detail == "afferma che il corpo è retrogrado, ma le voci citate indicano: diretto."` | N/A |
| Cited entry whose natal point is an angle/node | a cited Aspect's `natal_point == "ascendant"` (or `midheaven`/`true_node`/`south_node`) | Renders `"Ascendente"` (etc.) — never the raw English token — both inside the cited-entry card's `"Punto natale"` field and, if that value ends up in a `gathered` set, inside `detail` | N/A |
| Violation with cited entries | `entry_ids` non-empty, ids resolve in `stored_payload.payload` | One small card per cited entry: Italian field labels, localized timestamps, id chip | N/A |
| Violation with no citations | `entry_ids == ()` | No cited-entry card block rendered; "nessuna" chip text unchanged | N/A |
| Stale/unresolvable entry id | an id absent from `stored_payload.payload` (should not happen for a real Gate run) | Render just the id chip, skip the card silently — never crash the page | N/A |
| Gate-failed poll view | `run.failed_at` set, `gate_failed` True | Centered `.btn.btn--danger` reading "Verifica non superata" replaces the plain link; links to `/draft` unchanged | N/A |

## Design Notes

**Why fix `core/` now.** Story 9.9 fenced `core/` off to contain *that*
story's blast radius, not because `core/` can never carry Italian text —
`_ITALIAN_MONTHS` is already there. Four deterministic detail templates,
enumerable categories: same risk as any other string swap, one file away
from where 9.9 drew its line.

**Cited-entry card, not a full payload dump.** Only the fields the matched
event's own dataclass declares (5-7 rows; up to 8 for `TransitAspectEvent`)
— never `schema_version`/hash internals. Booleans render "Sì"/"No"; the
outer `"kind"` tag is the card's Italian heading (`Aspetto`, `Stazione`, …),
never a raw dict key.

**One shared translation, not two.** `body_sign_label()` lives in
`core/gate/run.py` (next to `_BODY_MAP`/`_SIGN_MAP`, the maps it inverts)
and is imported by `shell/http/stage_view.py` rather than reimplemented
there — `shell/` may import `core/` (only the reverse is forbidden, AD-1),
so one function serves both the `detail` sentence and the cited-entry
card's body-name fields with no duplicate table to drift out of sync.

**Per-category phrasing, not one flat template.** A translated planet/sign
name is self-descriptive ("afferma Saturno" already reads as a claim about
a body) and gets no wrapping noun; a bare house/day number is not
("afferma 7" is meaningless) and keeps one ("la casa 7"/"il giorno 8").
Review-loop 0's single `f"afferma {label} {values}"` template read as
grammatically awkward for exactly these two categories — this is the
concrete fix, not a stylistic preference.
