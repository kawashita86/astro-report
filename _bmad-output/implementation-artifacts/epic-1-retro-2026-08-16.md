### Diff-scope review (bmad-review: adversarial, edge-case-hunter, verification-gap)

Three lenses ran in parallel against `git diff 562378819b5e...d8c37c6714...`. Overlap between independent lenses is treated as signal, not duplication. Every finding below was re-verified against the primary source (file re-read, or a direct repro) before inclusion; findings that did not survive verification, or that duplicate an already-recorded `deferred-work.md` entry, are listed separately under "Accepted deviations" and were dropped from Action items.

**New, verified findings:**

1. **`verify_session()` can raise an uncaught `ValueError` instead of returning `False`.** `shell/http/auth.py:85` gates on `expires_at_raw.isdigit()` before calling `int(expires_at_raw)`. `str.isdigit()` accepts Unicode "digit" characters (e.g. `'3²'.isdigit()` → `True`) that `int()` cannot parse (`int('3²')` → `ValueError`), confirmed by direct repro. This breaks the function's own documented contract ("every failure mode... returns the same `False`") with an unhandled exception inside `AuthMiddleware` on a crafted `Cookie` header. Found independently by both the adversarial and edge-case-hunter lenses. Fix: `.isdecimal()` in place of `.isdigit()`, or wrap the `int()` call.
2. **`tests/test_ci_workflow.py` verifies the CI workflow by raw substring match, not structure.** Its push-trigger assertion (`tests/test_ci_workflow.py:33-37`) checks `"push:" in content` and `"main" in content` against the whole file, including the header comment — which itself contains the word "main" independent of the real `on.push.branches` value. Unlike its sibling `tests/test_dockerfile_ephemeris_build.py`, which strips comments before asserting on structure, this test would not catch the CI trigger being narrowed away from `main`. Found independently by both the verification-gap and adversarial lenses. Fix: parse the YAML (or strip comments) before asserting on the trigger config.
3. **The conformance harness has no way to check the exact fixture it ships with.** `tests/conformance/fixtures/retrograde-station-month.toml`'s own `note` field states a future computation "is expected to report an exact station moment inside this range, not equal to either bracket endpoint" — but `compare()`/`_walk()` in `tests/conformance/runner.py` only ever does strict equality, and the fixture stores a `bracket_start`/`bracket_end` pair with no field representing a single computed value to compare against at all. As authored, this fixture is structurally unpassable under the harness that will run it. Neither story's own review caught this: 1.6 tested `compare()` only against synthetic data, 1.7's review scoped fixture authoring, not harness capability — a genuine cross-story seam. Actionable when Epic 3's station-detection work (`3-2-date-every-station...`) lands: either add an interval-aware comparison mode, or restructure this fixture's `expected.stations` shape.
4. **Every fixture's aspect/transit-event values were derived by an uncommitted script.** Per spec-1-7's own Design Notes (line 96), all `[[expected.aspects]]`/`[[expected.transit_events]]` entries across the 7 fixtures were computed "by a throwaway script from the transcribed real longitudes" — confirmed no such script (or equivalent formula doc) exists anywhere in the repo. Those specific fields are currently unauditable/unreproducible if a future rounding or orb-boundary disagreement arises. Fix: commit the script or document the formula.
5. **`_ENVIRONMENT_MODULES` omits the real `environs` package.** `tests/test_env_access_is_centralized.py:35` denylists `dotenv`, `environ`, `decouple`, `pydantic_settings` but not `environs` (plural) — a distinct, real PyPI package. A module importing it would add a second environment reader undetected by the guard whose whole purpose is catching exactly that. Minor; one-line fix.
6. **`Rulers`/`ComputationConfig` are frozen dataclasses that are not actually hashable.** `core/types/computation.py:59-69` wraps `Rulers`' fields in `MappingProxyType`, which delegates `__hash__` to the underlying mutable `dict`; `hash(Rulers(...))` raises `TypeError: unhashable type: 'dict'` (confirmed by repro), and the same propagates through `ComputationConfig`'s dataclass-generated `__hash__`. Inert today — nothing hashes a `ComputationConfig` yet — but "frozen dataclass" reasonably implies hashable, and Epic 2+ reaching for `functools.lru_cache` or a dict keyed on config would hit a surprising runtime error with no hint from the type itself. Recorded as an open design note, not an urgent fix.
7. **`_check_for_unlisted_files` only scans the top level of `data/ephemeris/`.** `core/ephemeris/identity.py:134-149` filters to `path.is_file()` over `iterdir()`, never recursing, resting on an unstated assumption that pyswisseph never resolves ephemeris files from subdirectories. Found independently by both the adversarial and edge-case-hunter lenses. Low severity (no subdirectories exist today); worth a one-line comment documenting the assumption.
