### Aggregate views

- **God-class/size growth — clean.** Current sizes of the epic's top-churn files: `driver.py` 385
  lines, `aspects.py` 362, `sections.py` 311, `ingresses.py` 270, `lunations.py` 252, `stations.py`
  223, `freeze.py` 191, `assemble.py` 149, `report_runs.py` 143, `payload_view.py` 59. Each has one
  clear responsibility; no god-class.
- **Duplication — new finding.** `_bisect()` and `_build_grid()` (plus the `_BISECTION_ITERATIONS =
  40` constant) are reimplemented identically across `core/transits/aspects.py:212,260`,
  `stations.py:183,201`, `ingresses.py:210,248`, and `lunations.py:185,229`. Each copy's own
  docstring says it "mirrors" the canonical one in `aspects.py` — every one of the four stories saw
  the duplication and left it rather than extracting a shared helper. Distinct from
  `deferred-work.md:199`, which flags `_GRID_STEP`/`_BISECTION_ITERATIONS` drifting from
  `ComputationConfig`, not the code duplication itself. Verified by direct read: confirmed at all 8
  cited locations.
- **Architecture delta / purity — clean.** No `core/transits/*` or `core/payload/*` module imports
  from `shell/` or performs I/O; `ComputationConfig`/`SectionsConfig` enter only as parameters
  (AD-1/AD-11/AD-18 hold). `shell/runner/driver.py::drive()` (`driver.py:331-385`) is forward-only,
  commits after each stage, and reads state back from the row rather than in-process — matches
  Story 3.5's AC, covered by `tests/test_runner_driver.py:284,320,347` (retry-then-succeed,
  persistent failure, failure-after-partial-success).
- **Pattern divergence — clean.** The cross-module use of underscore-prefixed helpers
  (`day_lists.py:18-19` importing `_match_aspect`/`_natal_targets`) matches the identical convention
  already established by `stations.py:45`, `lunations.py:56-57`, `ingresses.py:49` for
  `_calc_body`/`_julian_day_ut`/`_house_for_longitude`. `core/errors.py`'s new `SectionsConfigError`
  follows the same typed-exception convention as earlier epics' error types. No new drift.
- **Spec-to-implementation reconciliation — AD checks:**
  - AD-2 (ephemeris identity recorded): confirmed, `freeze.py:179-182`.
  - AD-4 (stable hash ids, total order): confirmed, `freeze.py:119-127` — SHA-256 of
    `canonical_json_bytes(fields)`, sorted by the same key.
  - AD-5 (day-list projection pure): confirmed, `day_lists.py` is a pure table-driven classifier.
  - AD-10 (forward-only/idempotent/resumable from Postgres): confirmed as above.
  - AD-12 (UTC→local only in `shell/http/`): confirmed — `payload_view.py:19-47`'s `_localize_value`
    is the only conversion site, a generic ISO-8601 deep-walk, not key-name special-casing.
  - AD-13 (no per-Section branch): confirmed, `assemble.py:65-77` is driven entirely by
    `sections_config.sections.items()`.
  - AD-18 (config always explicit): confirmed, no ambient config access anywhere in the epic's new
    `core/` code.
  - `REPORT_RUN`/`REPORT_PAYLOAD` cascade: confirmed in `_CLIENT_CASCADE_TABLES`
    (`shell/adapters/postgres/client.py:44-45`), covered by the existing generic invariant test
    (`tests/test_client_store.py:282`) plus a story-3.8-specific one
    (`tests/test_report_payload_store.py:236`).
- **Recurring self-validated conformance-fixture pattern.** Story 3.1 corrected
  `no-lunations-month.toml`'s and `retrograde-station-month.toml`'s `transit_positions` (mercury,
  mars, jupiter longitudes) using its own new `find_transit_aspects()` output as the corroborating
  reference (`correction_2026_08_18`, both files) — backed by "well-documented" public events, not a
  cited independent source. Story 3.2 corrected the Mercury station bracket longitudes in
  `retrograde-station-month.toml` the same way, citing only "Story 3.2's real `find_stations()`
  computation" as the correction's authority (`correction_2026_08_19`). This is the identical
  circular-validation pattern epic 2's retro already flagged (still-open
  `epic-2-retro-item-15`) — it has now recurred in two more stories across this epic. By contrast,
  Story 3.4's own lunation-fixture correction (`no-lunations-month.toml`, `two-lunations-month.toml`)
  *is* independently corroborated (astropixels.com's Six Millennium Catalog, NASA, timeanddate.com,
  lunaf.com cited by name) — not every correction in this epic has the same weakness, but two of them
  do.

### Diff-scope review (bmad-review lenses: adversarial, edge-case, verification-gap — run at the
story boundaries: 3.1-3.4→3.6, 3.6→3.7, 3.7→3.8, 3.8→3.9)

- **Poll view has no stuck/failure state.** `shell/runner/driver.py::drive()` (`driver.py:368-376`)
  deliberately catches any exception, logs it, and leaves `run.stage` unchanged for the next retry —
  documented, deliberate design (`shell/runner/backoff.py`'s own docstring), and unit-tested
  (`tests/test_runner_driver.py:320`). But `report_run_poll.html` always renders
  `Stage: {{ run.stage or "starting" }}` and polls every 2s indefinitely
  (`hx-trigger="every 2s"`), with no branch for "this will never advance." No HTTP-level test exercises
  the poll response for a permanently-stuck run. This is the user-facing surface of two
  already-deferred causes (`deferred-work.md:238-239` no concurrency control, `:242` deterministic
  errors retried as transient) — neither of those items mentions that the poll view itself gives
  Francesco no way to tell "still working" from "stuck forever." Verified by direct read of both
  files.
- **Payload entry ordering is content-hash order, not chronological.** `freeze.py:119-127` sorts
  entries by `canonical_json_bytes(fields)` (AD-4's total-order requirement), and
  `report_payload.html` renders each Section's entries in that exact stored order with no re-sort —
  within a homogeneous group the effective order is aspect-type/natal-point/body alphabetically, with
  date as a late tiebreaker. Deliberate and tested (`tests/test_payload_freeze.py:187,318`), not a
  defect — but Story 3.9's own stated purpose ("when a client asks 'why do you say that?' mid-call I
  can answer in one sentence," `epics.md:1068-1069`) plausibly wants a chronological reading order in
  the *display*, distinct from the *stored* total order AD-4 requires. Recorded as a spec-
  interpretation observation, not routed as a defect.
- Everything else checked at the story boundaries came back clean: the 3.1-3.4→3.6 event
  serialize/deserialize round-trip (`driver.py:169-278`, mirrored in `freeze.py:105-116`) is symmetric
  per event kind; 3.6→3.7 ordering (`driver.py:308-311`) assembles before projecting day-lists;
  3.7→3.8 ordering (`driver.py:312-318`) freezes `payload` and `day_lists` together, so freeze can
  never run ahead of day-list classification.
