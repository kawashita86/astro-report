# Epic 9 Context: Rebuild the operator interface against a real design contract

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Turn sixteen standalone, unstyled full-HTML pages into one styled application: a persistent Italian-language shell with a sidebar, light and dark themes, density-appropriate forms and reading views, and real feedback (loaders, toasts, a live stage track). This is a presentation-layer rebuild only — server-rendered templates, a vendored token stylesheet, a vendored HTMX, and one new `/` route. No domain (`core/`) change, no functional-requirement change, no data-model change. The epic realizes the binding UX design contract (EXPERIENCE.md + DESIGN.md) and, together with Epic 3 Story 3.10, the "watch a report run progress" capability. The WeasyPrint PDF export template is explicitly out of scope — a client deliverable that deliberately does not inherit the design system.

## Stories

- Story 9.1: The application shell — one styled layout every page extends
- Story 9.2: A home dashboard instead of a 404
- Story 9.3: The Clienti list and the client-scoped tabs
- Story 9.4: Client create, correct and delete — restyled, with a real delete guard
- Story 9.5: A stage track to watch, and a Gate failure that can be read
- Story 9.6: The report reading sheet and the Payload view, made readable
- Story 9.7: The Style Guide and Corpus screens, restyled
- Story 9.8: Feedback and state primitives — toasts, loaders, empty states, inline errors
- Story 9.9: Italian everywhere, and the accessibility floor

## Requirements & Constraints

- **Behavior is frozen.** Every route contract, FR behavior, and data model is unchanged; only presentation, navigation, feedback, and the run-advance trigger (Story 3.10) change. Epic 6 export/disposition, Epic 7 corpus/pairing, and Style Guide versioning (save forks an immutable new version; generation refuses with no version) all carry over untouched.
- **Progressive enhancement is mandatory.** Every destructive and data-writing action works with JavaScript disabled (full-page POST + redirect + inline banner). JS only upgrades: live stage polling, toasts, in-place disclosure, theme toggle, focus management — never a broken no-JS state.
- **Full Italian UI.** Every visible string is Italian per the EXPERIENCE.md label map; domain terms (Cliente, Tema natale, Report, Payload, Bozza, Verifica di fondatezza, Sezione, Affermazione, Guida di stile, Corpus) are fixed — a synonym is a defect. Dates `dd/MM/yyyy`, times `HH:mm`. `YYYY-MM` codes, hashes, and UUIDs stay Latin-alphanumeric and always render as mono chips. Native `date`/`time` pickers are kept, inheriting `<html lang="it">`.
- **Accessibility floor: WCAG 2.1 AA.** One `h1` per screen, ordered headings, `nav`/`main` landmarks, a skip-to-content link. Every action keyboard-operable; a visible focus ring on every interactive element; the only focus traps are the modal and drawer, each restoring focus to their trigger on close. Interactive targets ≥ 24×24px. Layout holds at 200% zoom / 400% reflow with no horizontal page scroll; wide tables and the Payload view scroll inside their own container. `prefers-reduced-motion` disables the stage-dot pulse, skeleton sheen, smooth-scroll, and toast slide.
- **Contrast floors (both themes):** body ≥ 7:1, secondary ≥ 4.5:1, non-text UI (borders, stage dots, focus ring) ≥ 3:1.
- **Success criteria:** no standalone-HTML template remains; `/` serves an authenticated dashboard; the backup-stale banner is global; starting a run returns immediately and the stage view advances one step per poll; keyboard-only and reduced-motion passes both succeed; no English string in the rendered UI; `uv run pytest` green.

## Technical Decisions

- **One base template.** Every page extends a single `base.html`; no page ships its own `<html>`/`<head>`. A test asserts no rendered page has a second `<html>`.
- **Vendored assets, loaded once.** `static/tokens.css` (the `#42297A` primary-50–950 ramp, semantic colors `success`/`warning`/`danger`/`info`, Inter nine-role type scale, 4px spacing scale, radius and elevation scales, all as CSS custom properties) and `static/htmx.min.js` are vendored in-repo and pulled once from the base layout — no per-template CDN `<script>`/`<link>`. Stack unchanged: FastAPI + Jinja2 + HTMX 2.x, server-rendered, no SPA; small vanilla JS for toasts, theme toggle, modal focus-trap, click-to-copy.
- **Themes.** Light and dark both authored in DESIGN.md; tokens redefined under `prefers-color-scheme` and overridable via a `data-theme` attribute set by a sidebar toggle.
- **AD-20 (non-blocking run driver), delivered by Story 3.10, consumed here.** The runner exposes a single `advance` function doing at most one stage transition then returning, invoked only from `GET /report-runs/{run_id}`. `POST /clients/{id}/report-runs` creates the row and returns immediately; the first stage runs on the first poll. A closed tab pauses the run at its checkpoint and resumes on the next poll. Story 9.5 is read-only against the stage AD-20 persists.
- **AD-15 (single principal), unchanged.** Every route stays authenticated by default; the allowlist (`/login`, `/healthz`) and its test are unchanged; `/` is authenticated. An unauthenticated browser navigation (`GET`/`HEAD`, HTML `Accept`, no `HX-Request`) to any guarded route now redirects (302) to `/login?next=<path>`, opening `next` on sign-in; any other caller shape keeps the existing empty-body 401 unchanged.
- **AD-17 (durability staleness), unchanged logic, surfaced globally.** The backup-stale warning (newest Report postdates the last recorded export) is promoted from one deep screen to a persistent global banner, clearing when a backup is recorded.
- **AD-10 (checkpointed run), unchanged**, extended by Story 5.7/5.8's human-resolved Gate paths: automatic regeneration still replaces the whole Report and increments `regeneration_count`; **Accetta** (5.7) and **Modifica e ricontrolla** (5.8) resolve one violation at a time without touching that count, and a Report closed via accepted violations must render as such (never identical to a clean pass) everywhere it appears.
- **Density split.** Lists/tables ~1120px, compact 40px rows, hairline dividers, ghost row-actions. Forms ~560px, label-above-input, ~24px field rhythm, helper text below. Report sheet 720px at `body-read`, 32px gaps between the eight Sections. Payload/draft/Gate views ~960px, typed disclosure. Dashboard ~1120px card grid. Structure via hairline borders and surface tints, not shadow; elevation reserved for toasts, modals, menus, popovers.
- **Out of scope:** `report_export.html` (WeasyPrint, Georgia serif) stays exactly as-is; a check must confirm it is untouched.

## UX & Interaction Patterns

- **Shell.** Persistent 240px sidebar: Home, Clienti, Guida di stile, Corpus, Backup; one active item with a marker; a theme toggle and `Esci` pinned to the bottom. Below 900px it becomes a focus-trapped off-canvas drawer from a header menu button. A sticky page header holds breadcrumb, the one `h1`, and the screen's single primary action; focus moves to the `h1` after a full-page navigation.
- **Home dashboard.** Recent `ReportRun`s by Client and month with current stage/terminal status as a badge; the global backup-stale banner; quick actions to Clienti and Guida di stile. Each recent-run row is a link — to that run's Report if passed/exported, otherwise its stage view.
- **Clienti list + tabs.** Client-side name filter (no server round-trip); an empty result shows an inline "nessun cliente corrisponde" line, not the list's empty state. Superseded charts badged on the row. A selected Client shows a contextual tab row (Anagrafica / Tema / Report), each its own route, active tab derived from the path, agreeing with the breadcrumb. The Report tab offers **Nuovo report** — a single `YYYY-MM` field posting to the existing `POST /clients/{id}/report-runs`, landing on the run's stage view — absent/disabled for a Client with no stored chart. This is the only UI entry point to start a run.
- **Report-run breadcrumb.** Every report-run-scoped screen (stage view, Draft, Payload, Report) shows "Clienti / {client name} / {month}", both segments linking back.
- **Sign-in screen.** A centered flex column (not the base layout's left-aligned bare form), with a small decorative SVG wordmark above the password field, built from existing tokens only; same centered treatment at 320px and in both themes.
- **Forms.** On submit the primary button disables and spins; fields lock. Server validation errors re-render with per-field messages via `aria-describedby` plus a form-level summary that takes focus and links to each failed field. Birthplace disambiguation is an in-form sub-state (a candidate radio group) that preserves the typed input, not a new screen. The **correction** form prefills the birthplace field with the stored place name exactly like every other field — Francesco can reconfirm it as-is or replace it to correct it.
- **Confirm modal.** Focus-trapped, initial focus on cancel. Delete Client states in Italian exactly what is removed, and its destructive button stays disabled until Francesco types the Client's exact name. Correcting birth data (which supersedes the chart) is a plain confirm — no typed name — stating the prior chart is kept, marked superseded, and stays consultable.
- **Stage track.** Six nodes — tema natale, transiti, Payload, bozza, verifica di fondatezza, esportazione — each pending/active/done/failed with an Italian caption; the active-dot pulse suppressed under reduced motion. Reopening a run shows its true current stage and resumes on the next poll — no lost work implied. A non-Gate failure shows the failed node in `danger`, naming the stage and why.
- **Gate failure is a destination, not a toast.** A `danger` panel headed "Verifica di fondatezza non superata" shows one card per violation — kind, Sezione, the offending sentence as a blockquote, detail, cited entry IDs as mono chips (or "nessuna") — each linking to its Sezione below. Primary action **Rigenera** (whole-Report replace, increments `regeneration_count`). Each card also offers **Accetta** (records the acceptance against that violation, permanent) and **Modifica e ricontrolla** (an inline textarea prefilled with the sentence, re-checks only the Gate, never touches `regeneration_count`) — both act on that one violation alone. A Report completed via one or more accepted violations is visibly marked "passed with N accepted exceptions" wherever it appears — stage track, reading sheet, Report History — never shown identically to a clean pass.
- **Report sheet.** 720px, `body-read`, eight Section titles at `heading` weight with 32px gaps, an in-page section nav that scroll-spies the active Section, a `small` regeneration-count note, and the Epic 6 export bar unchanged.
- **Payload view.** Typed disclosure per Section (`<details>`/`<summary>`, works without JS), collapsed beyond the first, replacing the recursive `<dl>`/`<ul>` dump; every entry ID a click-to-copy mono chip ("Copiato" for ~1.5s).
- **Toasts.** Top-right `aria-live` region: success auto-dismisses ~5s, warning/danger persist with a close control, at most 3 visible, FIFO. With JS disabled the same outcome is a dismissible inline banner.
- **Loaders / empty states.** A skeleton matching the final layout for a known-shape HTMX region; an inline button spinner + `aria-busy` for a single indeterminate action. Each list surface (Clienti, a Client's Reports, Corpus, Style Guide before v1, dashboard recent runs) has a one-line Italian empty state with one primary action. A failed stage-view poll shows a non-destructive inline banner, backs off (5s then 15s), and offers a manual "Riprova" after the second failure.
- **Style Guide / Corpus.** Rendered readable at `body-read`; `<pre>` only for literal code. The editor carries an `info` banner that saving forks a new version. Corpus entry text clamps to ~6 lines with a working Expand control; paired/unpaired composition counts shown.

## Cross-Story Dependencies

- **Depends on Epics 1–7 being done** and on **Story 3.10 (AD-20)** landing first — Story 9.5's stage view reads the stage that Story 3.10's poll-driven `advance` persists.
- **Build order is fixed: 9.1 first**, because every other 9.x extends the shell, token stylesheet, and base layout it creates; then 9.2 → 9.9 in order.
- **9.8 (feedback/state primitives) underpins earlier screens** — toasts, skeletons, empty states, inline form-validation are used by 9.2–9.7; build minimal versions inline and consolidate into shared partials in 9.8, or pull 9.8's primitives forward as needed.
- **9.9 (Italian sweep + a11y floor) is a cross-cutting finishing pass** over every screen from 9.1–9.8.
- **9.5's Gate-failure panel wires up existing Epic 5 routes** — Accetta and Modifica e ricontrolla call Story 5.7/5.8's endpoints, which are already built by the time Epic 9 runs; 9.5 adds no new backend behavior, only the UI for actions that already exist.
- Francesco reviews each rendered screen against DESIGN.md / `mockups/` and signs off the Italian copy against the EXPERIENCE.md label map before a story is accepted.
